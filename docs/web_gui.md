# 웹 대시보드

프로젝트 루트의 `dashboard.zip`에 들어 있는 프런트엔드 레이아웃과 CSS를 React 화면에 옮겼습니다. 압축본의 Python 서버·SocketCAN 송신·SHM 구현은 사용하지 않습니다. 기존 Node WebSocket 서버와 C++ 읽기 전용 브리지를 유지합니다.

## 화면

- **Overview:** 실제 구동 상태, 현재/선택 모션, 모터별 Enable, HAL이 소비한 MIT 명령, CAN 통계, 관절각 다이얼, FK 궤적 추종 오차와 명령 이력.
- **Processes:** daemon이 관리하는 실제 프로세스의 PID·CPU·메모리·가동 시간·실행 명령과 시작/중지.
- **SHM Data:** ABI·크기·발행 번호, Motor/Model/Control 데이터와 Raw JSON. 잠금이나 내부 포인터는 전송하지 않습니다.
- **Cogging Identification:** MIT q 차분 속도와 기존 dq의 모터 각도별 리플·차수 스펙트럼·피크를 비교하는 읽기 전용 분석 화면.

Raw CAN 송신, 수동 C3/영점 오프셋·프리셋, 임의 모터 폴링, IMU와 별도 ESTOP 상태 머신은 추가하지 않습니다. 순차 스토퍼 제로셋, 기존 모션·Tracking 평면·목표 힘 입력은 유지합니다.

취득 불가·미수신·오래됨·미보정 상태를 숫자 0으로 대신하지 않습니다. CAN Load는 설정된 모터 ID의 TX/RX 카운터와 Classic CAN 최대 스터핑 기준의 추정치입니다. 전체 버스의 다른 노드·오류·재전송은 포함하지 않습니다. Applied MIT Command 표의 HAL 소비 번호도 모터 실제 적용 ACK와 구분합니다.

## 실행

```bash
cmake --build build --parallel 4
./scripts/run_daemon.sh                 # 준비된 물리 CAN 세션
# 또는 ./scripts/run_simulation.sh      # vcan + MuJoCo OpenGL GUI
# 또는 ./scripts/run_hw_deploy_test.sh  # 가상 모터 + OpenGL
# 웹 GUI도 자동 시작: http://127.0.0.1:8080
```

최초 의존성 준비는 `./scripts/run_web_gui.sh --setup`입니다. 프런트엔드는 실행 때 빌드하며 보통 시작에서는 네트워크 설치를 하지 않습니다. URL은 `http://127.0.0.1:8080`입니다. 기본 물리·시뮬레이션·시각화 daemon 설정에 선택 프로세스 `web_gui`를 등록했습니다. 웹 오류는 로그로 표시하며 로봇 세션을 종료하지 않습니다. 수동 실행이 필요하면 `run_web_gui.sh`를 별도로 사용할 수 있습니다.

```bash
./scripts/run_web_gui.sh --shm-name /qhrr05 --port 8080 \
  --control-config config/control/control.yaml
```

데몬이 종료되어 SHM이 삭제되거나 같은 이름의 새 세션으로 교체되면 수동 실행한 웹 서버도 이유를 출력하고 종료합니다. 스택만 중지한 경우에는 같은 SHM 세션이 유지되므로 웹에서 다시 시작할 수 있습니다. 이미 다른 웹 서버가 8080 포트를 사용 중이면 명시적인 오류로 중단합니다. 이전 웹 서버를 종료하거나 `--port`로 다른 포트를 지정해야 하며, 자동 포트 변경이나 기존 서버 강제 종료는 하지 않습니다.

프로세스 관리와 축별 요청 필드 추가로 **SHM ABI 22**을 사용합니다. 이전 세션은 모든 참여 프로그램을 새 바이너리로 다시 시작해야 합니다. `run_visualization.sh`와 웹 서버 실행 파일 경로는 유지합니다.

## 실시간 코깅 위상 튜닝

Overview의 State Machine 아래에서 HR·HP·KP의 21차/36차 위상을 조절합니다. 패널 위의 **0.1 / 0.25 / 0.5 rad** 버튼으로 스텝을 선택하고(기본 0.5), ▲/▼로 선택한 만큼 증감합니다. 위상 숫자에 포커스를 두면 ↑/↓ 키도 같습니다. 목표 위상과 적용 위상은 `0 ≤ φ < 2π` 범위에 표시하며 2π는 0으로 순환합니다. 제어기가 `anticogging.phase_slew_rad_s`(기본 5 rad/s, 0.5 rad당 약 0.1초)로 적용값을 서서히 바꿉니다. YAML의 `anticogging.enabled`가 꺼져 있거나 제어기 응답이 없으면 버튼은 비활성입니다.

각 차수 아래의 **보상 진폭 · 모터축 Nm** ▲/▼는 `amp21_motor_nm` 또는 `amp36_motor_nm`를 **0.01 Nm**씩 바꿉니다. 음수 진폭은 허용하지 않습니다. 목표 진폭과 적용 진폭을 따로 표시하며 `amplitude_slew_nm_s`(기본 0.1 모터 Nm/s)에 따라 한 단계를 약 0.1초에 적용합니다. 축 아래에는 감속비·scale을 반영한 보상 계산값(출력축 Nm)도 표시합니다.

클리핑이 계산되면 해당 축에 **모터축 보상 토크 한계 / 보상 전류 한계 / 합산 토크 한계 / CAN 토크 범위** 중 원인을 경고합니다. 마지막 클리핑을 1초 유지하므로 짧게 발생해도 확인할 수 있습니다. 설정 진폭 자체는 유지되며, 출력은 기존 한계로 제한됩니다.

위상·진폭 초기값은 YAML에서 읽으며 현재 프로세스에만 적용합니다. 브라우저 재연결은 현재 값을 읽고, 제어기 재시작은 YAML 값을 읽습니다. 파일은 자동 저장하지 않습니다. 기존 Input의 검증/응답 경로를 사용하고 SHM ABI 변경은 없습니다. 계산 토크 전환 및 CAN 양자화 한계는 [제어 문서](control.md)의 21·36차 코깅 보상 설명을 참고하십시오.

## Tracking ILC 런타임 설정

Overview의 **궤적 추종 오차** 바로 위에서 `phase_lead_bins`, `smoothing_passes`, `retention`을 조정합니다. 현재 값은 실행 중인 제어기에서 읽습니다. 입력이나 Enter는 전송하지 않으며 **반영** 버튼을 누르면 세 값을 함께 검증하고 적용합니다. 위상 선행은 `0..phase_bins/4` 정수, 필터 반복은 `0..32` 정수, 유지율은 `0 < retention ≤ 1`이며, 유지율 화살표 간격은 0.01입니다. ILC가 YAML에서 비활성화되어 있거나 제어기에 연결되지 않으면 입력을 비활성화합니다.

변경은 다음 학습 테이블 갱신부터 사용합니다. 현재 출력과 학습 테이블을 초기화하지 않으며 기존 갱신량 제한과 `blend_sec`를 유지합니다. Tracking에 다시 진입하면 기존 동작대로 학습 테이블은 초기화하지만 런타임 파라미터는 유지합니다. 프로세스를 재시작하면 YAML 값으로 돌아가며, YAML 파일은 자동 저장하지 않습니다. 기존 Input 소켓을 사용하고 SHM ABI는 변경하지 않습니다.

## GM 추정 반력

Overview의 Robot State 아래 **추정 반력** 패널에서 모델 XYZ 좌표계의 `Fx`, `Fy`, `Fz`, 크기 `|F|`를 N 단위로 확인합니다. 기존 SHM의 `ControlData.magnetic.estimated_force`를 읽으며 일반 상태 전송과 같은 20 Hz로 최신 값과 최근 10초 그래프를 표시합니다. 법선 방향 힘 `−n·F`는 접촉 추종(Following)·해제(Releasing) 중에만 표시합니다.

현재 GM 옵저버는 Magnetic 모드에서 실행되므로 해당 모드의 구동이 활성화되어야 표시됩니다. 다른 모드·출력 해제·옵저버 무효·제어기 또는 모터 피드백의 0.5초 이상 갱신 중단 시 숫자는 `—`로 바뀌고 그래프도 비웁니다. 다시 유효해지면 새 구간부터 표시합니다. SHM 정의나 제어 계산은 변경하지 않으며 웹 브리지를 빌드하고 웹 GUI 프로세스만 재시작하면 적용됩니다.

## FK 궤적 추종 오차

Overview의 **궤적 추종 오차** 패널은 Tracking 실행 중 목표/실제 궤적, XYZ 부호 있는 오차, 3D 오차 크기, 최근 10초의 축별 RMS·3D RMS·최대 3D 오차를 mm로 표시합니다. 목표는 기존 `ControlData.tracking_position_reference`, 실제는 기존 `MotorData.feedback.position`으로 웹 브리지의 독립된 MuJoCo 모델에서 계산한 FK입니다. 모델은 웹 실행 시 전달한 control YAML의 `model_path`를 사용하므로 제어기와 같은 설정 파일을 전달해야 합니다. 토크를 각도로 변환한 MIT 명령이나 `MotorData.reference`, SHM의 이전 모델 FK는 비교 목표로 사용하지 않습니다.

Overview를 보는 클라이언트가 있을 때 기존 SHM을 비차단 방식으로 500 Hz 읽고 FK를 계산합니다. 같은 피드백 수신 번호는 중복 집계하지 않습니다. 브리지→Node 전송은 20 Hz 배치이며 Node가 전체 표본의 통계를 계산합니다. 브라우저에는 4 Hz로 표시용 축소 파형과 통계만 보냅니다. 파형을 줄일 때 각 구간의 최대 오차 표본도 남깁니다. 목표/실제 궤적은 선택된 Tracking 평면(XY/XZ/YZ)에 투영하지만 3D 오차 통계에는 세 축이 모두 포함됩니다.

트래킹 시작·평면 변경·보정되지 않은 피드백·사전 궤적 검사 시 이전 통계를 초기화합니다. 새 피드백이 0.5초 동안 없으면 수집 중단을 표시하고 현재값은 `—`로 바꿉니다. SHM 정의, 제어기, CAN 송신 및 운전 모드는 변경하지 않습니다. 웹 브리지를 빌드하고 웹 GUI 프로세스만 재시작하면 적용됩니다.

## Cogging Identification

`/cogging` 또는 상단 메뉴에서 열고 **측정 시작**을 누릅니다. 분석 설정과 시작·일시정지·버퍼 초기화는 웹 서버에만 적용되며 구동 모드나 출력은 바꾸지 않습니다. 이 화면에서는 제어 단축키도 보내지 않습니다. 원하는 모터 운전은 기존 Overview에서 별도로 설정합니다.

```text
기존 MotorData → 읽기 전용 웹 브리지 500 Hz → Node 서버의 차분·LPF·각도 보간·FFT → 브라우저 4 Hz 표시
```

한 명 이상이 측정 중일 때만 브리지가 기존 SHM을 2 ms 목표 주기로 읽습니다. 새 `received_sequence`의 MIT 위치·속도·`measurement_ns`만 분석하며, 원시 고속 샘플은 브리지에서 서버까지만 전달합니다. 서버가 계산한 스펙트럼·피크·통계와 표시용으로 줄인 파형만 브라우저로 전송합니다. 브라우저에서는 FFT를 실행하지 않습니다. 일반 상태 전송은 기존 20 Hz입니다. 읽기는 비차단 잠금을 사용하며 놓친 샘플·중복·시각 초기화·C3 좌표 변경을 구분합니다. SHM 정의·생산자·제어기 및 CAN 송신은 변경하지 않습니다.

서버는 **모터 기계각 `θ_motor = 감속비 × 누적 MIT q`**를 분석 좌표로 사용합니다. q 차분 속도는 측정 시각의 실제 간격으로 계산하고 선택적 1차 LPF를 적용합니다. 같은 엔코더 코드가 반복되면 다음 위치 변화까지의 시간을 차분에 포함합니다. 기존 dq는 별도 신호로 유지합니다. 두 속도를 **동일한 모터 각도 간격으로 보간**한 후 각도 평균 제거·periodic Hann 창·FFT를 적용합니다. 시간 FFT의 Hz를 평균 속도로 나누는 방식이 아닙니다.

감속비(기본 9), 분석 구간(모터 0.125/0.25/0.5/1/2/4/8/16회전), FFT 점 수(128~4096), 최대 표시 차수를 선택합니다. 기본 1회전 구간의 차수 간격은 `1 cycles/rev`이며 6차는 모터 1회전당 6주기입니다. 진폭은 **출력축 속도 단측 peak(rad/s)**입니다. LPF 설정의 Hz만 시간 주파수이며 차수와 구분합니다. 보간으로 높은 차수 정보가 생기지는 않으므로 표시 상한은 `min(N/(2×회전 수), 1/(2×원본 최대 각도 간격[rev]))`으로 제한합니다.

감속비 9에서 기본 구간은 출력축 40°이며, 5°·10°·20°의 부분 회전도 선택할 수 있습니다. 짧은 구간은 더 작은 가동 범위에서 측정할 수 있지만 차수 간격이 각각 8·4·2차로 넓어집니다. 화면의 구간 선택에는 실제 출력축 이동각을 표시합니다. LPF 초기 안정화에 쓰는 앞부분은 분석 각도에 포함되지 않습니다.

최신의 연속된 한 방향 회전 구간을 사용합니다. 정지(100 ms 이상 위치 변화 없음)·방향 반전 후에는 마지막 완료 구간을 표시하면서 새 방향의 각도 구간을 채웁니다. 미완성 왕복을 합쳐서 더 넓은 각도 범위를 만든 것으로 취급하지 않습니다. 큰 수신 공백 후에는 새 구간을 모읍니다. C3/시각/시퀀스 초기화는 캡처 버퍼를 비웁니다. 파형의 가로축은 해당 구간 시작으로부터의 모터 회전수이고 스펙트럼·피크·CSV는 모두 **모터 회전 차수**입니다. 수신률, 방향, 원본 각도 샘플 수와 건너뛴 C0를 함께 표시합니다. 일시정지 상태에서도 마지막 구간의 분석 설정을 바꿀 수 있습니다.

주요 피크 표에는 **q=0 각도 원점에 대한 sin/cos 계수**를 함께 표시하며, CSV에는 표시 범위 내 모든 차수의 두 계수를 저장합니다. 정의는 `Δω_n(θ) = sine_n·sin(nθ) + cosine_n·cos(nθ)`, `θ = 감속비 × q [rad]`입니다. 진폭은 `sqrt(sine_n² + cosine_n²)`, 계수 단위는 출력축 rad/s입니다. 분석 구간의 시작 각도와 정·역방향에 대한 복소 FFT 위상을 보정하므로 창이 움직여도 각도 기준은 q=0으로 유지됩니다. 이는 속도 리플 계수이며 토크 계수가 아닙니다. q 차분 LPF를 사용하면 해당 계수는 필터의 진폭 감쇠와 위상 지연을 포함합니다. C3로 q 원점이 바뀌면 새 원점에서 다시 수집합니다.

MIT 출력축 q에 감속비를 곱한 기계각 추정이므로 감속비가 맞아야 합니다. 저속에서 양자화가 두드러지면 q 차분 LPF로 비교하세요. 이 화면은 속도 리플 식별용이며 토크 보상값을 쓰거나 제어기를 변경하지 않습니다.

적용은 웹 브리지 빌드 후 웹 GUI 프로세스만 재시작하면 됩니다. 제어기나 SHM 세션을 다시 만들 필요는 없습니다.

## 모터 Enable과 제어 입력

`Z`로 Zero set을 선택하고 `A`로 전체 Arm하면 기존대로 탐색합니다. `H/G/M/T/B/D`, `1/2/3`, 목표 힘 제어도 기존 Input 경로를 사용합니다. `X` 또는 Release는 전체 출력을 해제합니다.

개별 Enable/Enable All은 선택한 모터에 C1과 중립 MIT 명령(kp=kd=tau=0)을 전달하고 **ARMED**로 대기합니다. 실제 모션은 전체 Arm/Run으로 시작합니다. 활성 모션에서 한 축을 Disable하면 모션을 중단하고 남은 축도 중립 출력으로 바뀝니다. FAULT 중 재-enable은 거부하며 Clear fault 후 다시 명령해야 합니다.

웹 모터 명령은 `WebSocket → 기존 Node 서버 → Input → Safety → TaskController → SHM → CAN HAL` 경로입니다. 서버는 SHM이나 CAN에 직접 명령을 쓰지 않습니다. 승인·제어기 반영·동작 완료를 구분하며 연결이 끊긴 요청을 자동 재전송하지 않습니다.

## 프로세스 관리

프로세스 관리는 해당 프로세스가 멈춰도 사용할 수 있어야 하므로 기존 daemon에 별도 관리 엔드포인트를 둡니다. 경로는 `/tmp/qhrr05-daemon-<uid>/<session>.sock`이며 사용자 소유 0700 디렉터리와 SO_PEERCRED로 같은 UID만 허용합니다. PID·실행 파일·셸 명령을 받지 않고 daemon 설정에 등록된 프로세스 이름만 받습니다.

- 선택 프로세스(input/logger 등)는 개별 Start/Stop을 지원합니다. 수동 Stop은 자동 재시작을 억제합니다.
- 핵심 프로세스(control/CAN/가상 장치 등)는 전체 스택 단위로 시작·중지합니다. 개별 중지는 거부합니다.
- 스택 중지 전 모든 모터에 Release가 반영되어 있어야 합니다. daemon이 출력 활성화를 우회하지 않습니다.
- 스택을 중지해도 daemon·SHM·웹은 유지합니다. `keep_on_stack_stop: true`인 관리 UI는 재시작 때 중복 실행하지 않습니다. 다시 시작하면 새 관측/보정 상태에서 **DISARMED**로 시작합니다.
- 예상치 못한 핵심 프로세스 실패의 기존 전체 종료 정책은 유지합니다.

관리 엔드포인트가 없는 구버전 daemon에서는 이유를 표시하고 관리 버튼을 비활성화합니다. 다른 PID에 신호를 보내는 방식으로 대체하지 않습니다.

## 검증

```bash
npm --prefix apps/interfaces/web_gui/frontend test
npm --prefix apps/interfaces/web_gui/frontend run test:analysis
npm --prefix apps/interfaces/web_gui/frontend run test:browser
ctest --test-dir build --output-on-failure -R '^(hardware_deploy|safety_layer|control_io|daemon_lifecycle|can_hal_lifecycle|logging_service)$'
```

웹 통합 시험은 실제 Input·TaskController와 실제 daemon 자식 프로세스로 명령·프로세스 관리를 확인합니다. 브라우저 시험은 320/390/768/1280/1440px 화면, 키보드, 입력 편집 중 단축키 차단, 미적용 목표 힘, 연결 끊김을 확인합니다. 실제 모터를 구동하지 않습니다.

RMD Damping Constant 패널은 `rmd_damping_constant`의 현재 적용값을 표시합니다. 입력·화살표·Enter는 전송하지 않고 입력칸 옆 **반영** 버튼만 `rmd-damping` Input 요청을 보냅니다. 정수 0..100만 허용하며 재시작 시 YAML 값으로 돌아갑니다.
