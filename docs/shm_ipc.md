# qhrr-05 SHM IPC

`daemon`이 POSIX SHM을 생성·초기화하고, 자식 프로세스가 끝난 뒤 해제합니다. 기본 이름은 `config/app_config/daemon_config.yaml`의 `/qhrr05`입니다. 같은 이름이 이미 있으면 실패하며 기존 객체를 재사용·크기 변경·삭제하지 않습니다.

```bash
./build/daemon
./build/daemon --csv /tmp/qhrr05.csv
./build/daemon --shm-name /qhrr05_test --headless --duration 4 --csv /tmp/qhrr05_test.csv
```

`--csv`를 지정하면 daemon이 `shm_logger`도 실행합니다. 기존 CSV 파일은 덮어쓰지 않습니다.

## 독립 제어 주기

`config/control_config/control_config.yaml`에서 제어 주파수를 설정합니다.

```yaml
task_controller:
  frequency_hz: 1000.0
```

TaskController가 자기 항목을 읽고 검증하며, 각 모션 컨트롤러에는 같은 파일의 **경로 문자열**만 전달합니다. 각 모션 클래스가 자기 파라미터를 직접 읽고 검증합니다.

제어 수퍼루프는 `ReadInput → Control → WriteOutput → WaitNextCycle`입니다. monotonic clock의 절대 시각으로 주기 대기를 수행합니다. 궤적 시간도 제어기 시작 이후의 실제 monotonic 경과 시간입니다. OS 스케줄링·계산 시간에 따라 실측 간격은 달라질 수 있습니다.

매 주기 최신 관절 측정값을 읽고 자체 시퀀스의 명령을 발행합니다. 새 입력이 없어도 계속 계산합니다. 제어 입력에는 MuJoCo 시뮬레이션 시간이 없으며, 제어기는 run/pause/시뮬레이션 완료 상태를 읽지 않습니다. 제어기 자체의 주기 대기는 프로그램 공통 종료 요청으로 해제할 수 있습니다.

시뮬레이터도 명령을 기다리지 않고 최신 명령을 적용합니다. 물리 스텝과 제어 주기는 서로 다르거나 한쪽이 멈출 수 있습니다. 일시정지 중에도 제어 시간·명령은 진행하며, headless에서도 시뮬레이션 시간에 맞춰 제어기를 가속하지 않습니다. 최초 발행 이전에는 SHM 생성 시 초기화한 0 프레임을 사용하고 준비 완료를 기다리지 않습니다. 입력·명령의 최신 값을 유지하는 것이 정상 동작 정책이며, 응답 지연에 따른 자동 대체·중단·동기화는 없습니다.

## 데이터와 동기화

정의는 `include/shared_memory.hpp`, 매핑·잠금 유틸리티는 `include/shm_utils.hpp`에 있습니다. 각 채널은 **시퀀스 번호가 있는 두 슬롯**을 가지며, 작성자는 `sequence % 2` 슬롯을 채운 다음 발행 번호를 갱신합니다.

| 채널 | 작성자 | 내용 |
| --- | --- | --- |
| `states` | 관절 상태 제공자(현재 MuJoCo) | 위치·속도·중력 토크·모터 토크·차분 가속도·M/h/passive/J·발끝 위치와 측정/발행 시퀀스 |
| `requests` | GUI/외부 명령 제공자 | H/G/M 모드, 목표 힘, 발행·모션 시퀀스. 힘 슬라이더는 모션 시퀀스를 유지 |
| `commands` | TaskController | 독립 명령 시퀀스, 사용한 입력 시퀀스·발행 시각, 제어 시간, 토크·목표 자세·모션 상태 |
| `samples` | MuJoCo | run ID, 시뮬레이션 시간, 실제 각도·모터 토크·목표, 적용 명령의 관련 정보 |
| `joystick` | 선택적 aux_reader | 기존 축 매핑 3개와 버튼 11개 |

관절 순서는 FL hip / thigh / calf입니다. 슬롯 발행·스냅샷 복사는 짧은 프로세스 공유 mutex로 보호합니다. CSV 쓰기와 제어 계산은 잠금 밖에서 수행합니다. 잠금을 가진 프로세스가 죽으면 robust mutex 오류를 명시적으로 보고하고 세션을 종료합니다.

모드 전환과 재호밍은 `requests`로 전달합니다. 시뮬레이션 시간의 되감기를 제어기에서 검출하지 않습니다. GUI의 R은 물리 초기화와 함께 재호밍 요청을 명시적으로 발행합니다. daemon은 정상 프로그램 종료 시 공통 종료 요청을 보내며, 자식 프로세스의 비정상 종료 처리도 유지합니다.

## 로거의 평가

CSV는 기존 각도·목표·실제 토크와 함께 다음 값을 기록합니다.

| 열 | 의미 |
| --- | --- |
| `sample_seq` | 계측 발행 시퀀스 |
| `command_seq` | 실제 적용한 명령의 독립 시퀀스 |
| `state_seq` | 그 명령이 사용한 관절 입력 시퀀스. `command_seq`와 같을 필요 없음 |
| `control_time` | 명령에 기록된 제어기 자체의 경과 시간. `sim_time`과 독립 |
| `control_latency_us` | 명령 발행 시각 − 그 명령이 사용한 입력 발행 시각. 입력의 경과 시간도 포함하며, 순수 계산 시간은 아님. 최초 입력 발행 전이면 빈 칸 |
| `sample_age_us` | 로거 관측 시각 − 계측 발행 시각 |
| `skipped_samples` | 직전 관측 이후 놓친 계측 발행 수. 최초 연결 이전 누락도 포함 |

지연 계산과 누락 평가는 `shm_logger`에서만 수행하며 제어 피드백이나 자동 중단에 사용하지 않습니다. 로거는 계측뿐 아니라 명령 발행도 관측하여 입력→명령 발행 시간의 최대 관측값, 관측한 명령 발행 간격의 최대값, 명령 관측 누락 수를 종료 시 출력합니다. 관측 사이 명령이 여러 개 빠지면 명령 간격은 그 누락 구간을 포함합니다.

계측·CSV 행은 `plots.sample_hz`(기본 100 Hz)의 **시뮬레이션 시간** 기준으로 발행되므로 GUI 일시정지 중에는 새 계측 행이 정기 생성되지 않습니다. 그동안에도 제어 명령 관측은 계속됩니다. 로거가 늦으면 더블버퍼의 중간 프레임은 생략되며 이를 집계합니다. 생산자에 로깅 대기를 걸지 않으며 모든 제어 주기를 빠짐없이 기록한다는 보장은 없습니다.

조이스틱은 `./build/aux_reader /qhrr05 /dev/input/js0`으로 명시적으로 연결합니다. 현재 모드 선택은 GUI의 H/G/M이며 새 조이스틱 제어 기능은 매핑하지 않았습니다.

Magnetic Touch 확장에서는 `ShmState.measurement_sequence`가 실제 물리 측정마다 증가하며, 반복 프레임에서는 RFOB 필터를 재갱신하지 않습니다. `ShmCommand.magnetic`에는 관측·상태 머신 결과를, `ShmSample`에만 접촉 GT 힘/모멘트·물체 좌표를 둡니다. 목표 힘 변경은 요청 발행 시퀀스만 갱신하고 `motion_sequence`는 유지하여 제어 상태를 재시작하지 않습니다. 자세한 조작과 제한은 [Magnetic Touch 핸드오버](magnetic_touch_handover.md)를 참고하십시오.
